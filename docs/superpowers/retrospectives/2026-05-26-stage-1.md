# Stage 1 retrospective

**Date:** 2026-05-26, with a post-`v0.1.0` addendum recorded in the `v0.1.1` history.
**Reconciled:** 2026-09-13. Observations below are historical reports, not fresh
runtime verification. Original command output and resource IDs remain in Git
history. [Original design](../specs/2026-05-26-aws-demo-platform-design.md).

## Reported delivery

Stage 1 established repository/state ownership, Atlantis bootstrap, the private
ALB/CloudFront path and new ArgoCD system/tenant roots on the existing hub.
The author recorded a no-drift Terraform plan, Atlantis IRSA/assume-role checks,
healthy target registration and HTTP 200 health endpoints for Atlantis and ArgoCD.
Those checks established specific paths at that time, not complete public
application or future infrastructure health.

The ArgoCD cutover removed the old installation, reconciled CRD/Helm ownership
and registered the two Korean spokes. Tenant workload Applications, initial
account/project metadata and friend-account onboarding instructions were added.
Initial notes referenced Helm chart 7.8.13; the later addendum recorded ArgoCD
3.4.2/chart 9.5.15. Current manifests, not either historical version, are authoritative.

## Problems and lessons retained

| Issue encountered | Recorded response and lasting lesson |
| --- | --- |
| Terraform rejected `use_lockfile` | Used DynamoDB locking; current Atlantis remains pinned to 1.9.6 |
| Hub taints blocked scheduling | Added matching component tolerations |
| ESO was absent | Bootstrapped it and used the supported `external-secrets.io/v1` manifests |
| Atlantis GitHub App auth failed | Preserved `--write-git-creds` |
| HTTPS origin/SNI mismatch | Used a hostname covered by the existing wildcard certificate |
| CloudFront VPC Origin connectivity failed | Added its explicit source SG alongside `10.0.0.0/8` |
| Old ArgoCD finalizers/Helm ownership blocked replacement | Performed scoped cleanup/adoption; this was an incident action, not routine deletion guidance |
| Repository cache or old resource ownership caused sync errors | Refreshed repo-server and corrected manifests/ownership rather than treating health alone as sync proof |

## Post-tag addendum and limits

The addendum recorded operator/Terraformer trust verification, spoke registration,
and system Applications for Atlantis, ArgoCD, ESO and ClusterSecretStore.
MRA PRs #12–15 removed duplicate environment patches across tenant overlays;
rendering was reported clean. The snapshot listed eight Applications, six synced
and two still out of sync but healthy. It did not demonstrate that every deferred
item from the original plan had completed.

Originally deferred work included broader system adoption, observability routing,
Prometheus remote write, friend-account enrollment and upstream cleanup. Some
later landed in source: Tempo/ClickHouse have hub ApplicationSets, and Prometheus
manifests define remote write and its receiver. The proposed Tempo removal did
not become the final topology. No current friend-account enrollment or live
cross-repository cleanup state is asserted by this retrospective.
